# Football Imposter — Technical Documentation

This document is a complete technical reference for the Football Imposter codebase, generated by reading every file in `app/`, `components/`, `store/`, `data/`, and the root config files. It reflects only what is actually present in the code as of this writing.

---

## 1. Project Overview

**Football Imposter** is a party/social-deduction mobile game built with **Expo + React Native**. It is a football-themed variant of games like "Spyfall"/"Werewolf": a group of players (3–8) passes a single phone around. All players except one or two ("imposters") are shown the same secret football-related word (a player name, club, stadium, etc.). The imposter(s) are shown either `IMPOSTER` or, in "Similar Word" mode, a different-but-related word. After everyone has secretly viewed their word, the group discusses out loud, tries to identify the imposter(s) by their vague answers, and votes.

### Core game loop
1. **Home** — Splash screen with the app logo, tagline, "How to Play" link, and "Get Started" CTA.
2. **Setup** — Choose player count, imposter count, game mode (Same Word / Similar Word), and word category. Categories are chosen via a dedicated **Categories** screen.
3. **Players** (optional) — Rename the players (default names are "Player 1", "Player 2", …).
4. **Game** — A grid of player tiles. Each player taps their own tile to privately reveal their word (navigates to **Reveal**), then returns. Once every player has seen their word, the app auto-navigates to **Voting**.
5. **Reveal** — A tap-to-reveal card shows the current player's word (or "IMPOSTER"/the imposter's word).
6. **Voting** — A 4-step "how to vote" instructional screen (Starting Player → Group Discussion → Vote Time → Reveal Phase), then a "Reveal Results" button.
7. **Results** — Shows who the imposter(s) were and what the secret word was, then "Play Again" returns to Setup.

### Monetization
The **Active Players** category is entirely free. Every other category (9 total) is premium/locked and gated behind a paywall offering a weekly subscription or a lifetime one-time purchase, implemented with `expo-iap`.

### Internationalization
The UI is fully translatable via a custom `t()` function backed by 12 JSON dictionaries (English + 11 other languages), with English as the fallback for missing keys.

## 5. State Management Architecture

There are **three** persistence-backed stores plus one large React Context. They are architecturally independent — see Known Issues for the consequences.

### 5.1 `store/gameSettings.tsx` — `GameSettingsProvider` / `useGameSettings()` (React Context, not Zustand)
Wraps the entire app in `_layout.tsx`. Persists a subset of its state to AsyncStorage under key `gameSettings.v1`, debounced 250ms after hydration.

**Holds:**
- `playerList: {id, name}[]`, backward-compatible `players: string[]`
- `imposters: number` (fixed count), `randomImposters: boolean`, `randomMode: "balanced"|"custom"`, `randomMinImposters`/`randomMaxImposters`, `imposterNeverFirst: boolean`, `showImposterCount: boolean`
- `mode: "same"|"similar"`, `showCategoryToImposter: boolean`
- `isPro: boolean` (local state — see Known Issues, never actually toggled)
- `selectedCategories: Record<CategoryKey, boolean>`, `categoriesTouched: boolean`
- `playersSeenIds: string[]` / legacy `playersSeen: number[]` (index-based) — tracks who has viewed their word this round
- `round: RoundState` — `imposterIds` (Set<number>), `imposterPlayerIds`, `votingOrderIds`/`votingOrderIdxs`, `startingPlayerId`/`Idx`, `categoryKey`, `categoryTitle`, `commonWord`, `imposterWord`
- `votingUnlocked: boolean`

**Key actions exposed:** `setPlayerCount`, `setPlayerName`, `setImposters`, `setRandomImposters`, `setRandomMode`, `setRandomMinImposters`/`setRandomMaxImposters` (with min/max cross-clamping), `setMode`, `setShowCategoryToImposter`, `toggleCategory`/`selectAllCategories`/`clearAllCategories`, `markPlayerSeenId`/`markPlayerSeen`, `startRound`/`startNewRound`, `isPlayerImposter`, `resetRound`.

**Used by:** every screen except `home.tsx` and `settings/*` — most heavily by `setup.tsx`, `players.tsx`, `imposters.tsx`, `categories.tsx`, `game.tsx`, `reveal.tsx`, `voting.tsx`, `results.tsx`.

### 5.2 `store/purchaseStore.tsx` — `usePurchaseStore` (Zustand, **active**)
Persisted via `zustand/middleware`'s `persist` + AsyncStorage under key `purchaseStore.v1` (`isPremium`/`purchaseType` only; `hydrated` is excluded via `partialize`).

**Holds:** `isPremium: boolean`, `purchaseType: "weekly"|"lifetime"|null`, `hydrated: boolean`.
**Actions:** `setPurchase(type)`, `clearPurchase()`.
**Used by:** `app/_layout.tsx` (restores entitlement on launch via `expo-iap`), `app/categories.tsx` (gates premium categories, dev-only reset button), `app/paywall.tsx` (writes the entitlement after a successful purchase or restore, and auto-dismisses once `isPremium` becomes true).

### 5.3 `store/proStore.ts` — `useProStore` (Zustand, **legacy/orphaned**)
Persisted manually (not via `persist` middleware — hand-rolled `AsyncStorage.getItem/setItem` under key `entitlement_isPro_v1`).

**Holds:** `isPro: boolean`, `hydrated: boolean`.
**Actions:** `hydrate()`, `setPro(value)`, `resetToFree()`, `clearEntitlement()`. Includes a hardcoded dev-only flag `DEV_FORCE_FREE = false` that would force free mode on every launch in `__DEV__` if flipped to `true`.
**Used by:** `_layout.tsx` calls `hydrate()` on mount (so `isPro` is loaded from storage), and the unused `ProInfoModal.tsx`/`components/logic/gating.ts` read/write it. **No live screen reads `useProStore().isPro`** — its hydrated value has no effect on the running app today.

### 5.4 `store/billing.ts` + `store/useBilling.ts` — legacy one-time IAP helper (unused)
`billing.ts` defines the legacy product id `com.mzahariev.footballimposter.pro` and helper functions (`getIapDisplayPrice`, `buildProPurchaseRequest`). `useBilling.ts` is a React hook wrapping `expo-iap`'s `useIAP` to purchase/restore that single product and call `useProStore().setPro(true)` on success. **No screen calls `useBilling()`** — it exists only for the unused `ProInfoModal`.

## 6. Game Logic

All *live* round logic lives in **`store/gameSettings.tsx`**, inside the `startRound` function (aliased as `startNewRound`), called from `app/setup.tsx`'s `onStart` handler.

### Category & word selection
1. `enabledKeys` = every `CategoryKey` where `selectedCategories[key]` is true; if none are enabled, falls back to `"activePlayers"`.
2. `categoryKey` is picked **randomly** from `enabledKeys` (`Math.floor(Math.random() * enabledKeys.length)`).
3. `CATEGORY_DATA[categoryKey]` is looked up (each category module is normalized by the local `normalizeCategory()`/`normalizeWords()` helpers into `{ words, items?, similar? }`).
4. `getAllowedWords(data, isPro)` — if `isPro` is true, returns all `data.words`; otherwise filters `data.items` to only `free: true` entries, falling back to all words if that filtered list is empty. (See Known Issues: `isPro` here is the dead-end context state, always `false`, and — combined with all premium categories' items being `free: false` — the "otherwise" branch's filtered list is *always empty*, so this function *always* returns the full word list regardless of entitlement.)
5. Words already used this session for that category (`usedWordsByCategory[categoryKey]`) are excluded if any non-used words remain; `commonWord` is picked randomly from what's left via `pickOne()`.
6. If `mode === "similar"`, `imposterWord` is picked from that category's `similar[commonWord]` map (falling back to any different word in the pool) via `pickDifferent()`; in `"same"` mode `imposterWord` is left as `""` (imposters simply see `"IMPOSTER"`, resolved at render time in `reveal.tsx`).

### Imposter selection
1. `votingOrderIds` = `shuffle(playerIds)` (Fisher–Yates shuffle, `store/gameSettings.tsx`'s local `shuffle()`).
2. `starterId` = `votingOrderIds[0]`.
3. The eligible imposter pool (`poolIds`) excludes the starter if `imposterNeverFirst` is enabled.
4. The desired imposter count is computed from settings:
   - **Fixed mode**: `clamp(imposters, 1, effectiveMaxFixed)` where `effectiveMaxFixed = min(players - 1, MAX_IMPOSTERS)`, further capped by `imposterNeverFirst`.
   - **Random / Balanced**: a random integer in `[0, effectiveMaxRandom]`.
   - **Random / Custom**: a random integer in `[randomMinImposters, randomMaxImposters]` (both clamped to `effectiveMaxRandom`).
5. `poolIds` is shuffled again and the first `finalDesiredCount` ids become `chosenIds` (the imposters). A safety fallback guarantees at least one imposter in fixed mode if the random pick somehow produced zero.
6. Results are stored as both a `Set<number>` of legacy indexes (`imposterIds`) and a stable `imposterPlayerIds: string[]` array.

### Starting player selection
The starting player is simply **`votingOrderIds[0]`** — i.e., whoever lands first in the Fisher–Yates shuffle of all player ids for that round. There is no separate "pick a starter" step; the shuffle used for imposter-pool ordering doubles as the starting-player draw.

### Per-player reveal resolution
`app/reveal.tsx` computes `displayWord` at render time from the round + the player's index (passed via route params):
- If `mode === "same"`: imposter → `t("game.imposter")` ("IMPOSTER"), everyone else → `round.commonWord`.
- If `mode === "similar"`: imposter → `round.imposterWord` (or `"IMPOSTER"` if that's empty/unset), everyone else → `round.commonWord`.

### Standalone dead code: `logic/game.ts`
Exports `createRound(setup: GameSetup): RoleCard[]` — a much simpler, self-contained round generator (validates `playersCount` 3–8 and `impostersCount` 1–2, randomly assigns imposter seats, returns one `RoleCard` per seat). It is only imported by `app/pass.tsx`, which no screen navigates to, so this logic path is currently dead.

## 7. Data Layer

### Location
All word-bank data lives in `data/categories/*.ts`, one file per category, plus a shared `data/types.ts` (`WordItem = { id: string; value: string }`, used only by `legends.ts`'s `legends` export).

### Shapes (verified per file)
Every category file's item type includes a `free: boolean` field, though the surrounding structure differs:

| File | Item type | Fields | Count |
|---|---|---|---|
| `activePlayers.ts` | `ActivePlayer` | `name, club, nationality, position, free` | 200 |
| `plPlayers.ts` | `PLPlayer` | `name, club, nationality, position, free` | 150 |
| `legends.ts` | (via `WordItem` + inline `{name,free}`) | `id, value, free` (legends export) / `name, free` (items export) | 200 |
| `clubs.ts` | `ClubItem` | `name, similar: [5 strings], free` | 150 |
| `managers.ts` | `ManagerItem` | `name, nationality?, era?: "legend"\|"modern", free` | 100 |
| `stadiums.ts` | (plain `{name, free}`) | `name, free` (+ separate `stadiumClub` name→club map) | 50 |
| `referees.ts` | (plain `{name, free}`) | `name, free` | 30 |
| `nationalTeams.ts` | (plain `{name, free}`) | `name, free` | 100 |
| `leagues.ts` | `League` | `name, country, similar: string[], free` | 40 |
| `iconicMoments.ts` | (plain `{name, free}`) | `name, free` | 100 |

Every file also exports (in some combination) `words: string[]` (plain names, used for random selection), `similar: Record<string, string[]>` (5-per-entry "similar word" mappings for Similar Word mode), and a `default` export bundling these together, consumed by `store/gameSettings.tsx`'s `normalizeCategory()`.

### Free vs. premium
Confirmed by direct inspection of the compiled data (not just source):
- **`activePlayers.ts`**: all **200/200** items have `free: true` (forced unconditionally by a `players.forEach((p) => { p.free = true; })` pass at the end of the file).
- **Every other category** (`plPlayers`, `legends`, `clubs`, `managers`, `stadiums`, `referees`, `nationalTeams`, `leagues`, `iconicMoments`): **0 items** have `free: true` — all are `false`, either by a literal value, a forced `.forEach` override, or a computation that always evaluates to `false`.

This `free` flag feeds `store/gameSettings.tsx`'s `getAllowedWords()`, which is meant to restrict non-Pro users to free words within a category — but see §6 and Known Issues for why this mechanism is currently bypassed. The actual, effective gate for premium categories is at the **category-selection UI level** in `app/categories.tsx`, not the per-item `free` flag.

### Category registry
`store/gameSettings.tsx`'s `CATEGORIES` array is the single source of truth for category metadata used by the UI: `key`, `title` (an i18n key, e.g. `"categories.activePlayers"`), `icon` (emoji fallback), `sfSymbol` (SF Symbol name), and `count` (computed at import time from each category module's `words.length`).

## 8. Monetization System

**Two parallel, unconnected IAP systems exist in the codebase.** Only the second one is wired into the live UI.

### 8.1 Active system: weekly + lifetime paywall
- **Products** (`store/purchaseStore.tsx`): `PRODUCT_WEEKLY = "football_imposter_weekly"` (subscription), `PRODUCT_LIFETIME = "football_imposter_lifetime"` (one-time, non-consumable).
- **Purchase state**: `usePurchaseStore` (Zustand, persisted — see §5.2).
- **Where it's implemented**: `app/paywall.tsx` uses `expo-iap`'s `useIAP()` hook to fetch both products (`fetchProducts` with `type: "in-app"` for lifetime, `type: "subs"` for weekly), and offers a `PlanCard` selector (Weekly vs. "Best Value" Lifetime) with a single "Continue" CTA that calls `requestPurchase(...)` for whichever plan is selected. On `onPurchaseSuccess`, it calls `setPurchase("weekly"|"lifetime")`, finishes the transaction, and navigates back.
- **Gating**: `app/categories.tsx`'s `handleCategoryPress`/`handleSelectAll` check `isCategoryFree(key) || isPremium` (where `isCategoryFree` is true only for `"activePlayers"`); if the category is premium and the user isn't, it calls `router.push("/paywall")` instead of toggling selection. A `useEffect` safety-net also auto-deselects any premium category that ends up selected while `!isPremium` (e.g. from a stale persisted state).
- **Restore purchases**: implemented twice —
  1. **On app launch** (`app/_layout.tsx`): calls `initConnection()`, then `hasActiveSubscriptions([PRODUCT_WEEKLY])`, then (if that's false) `getAvailablePurchases()` checking for `PRODUCT_LIFETIME`, calling `setPurchase(...)` on a match, then `endConnection()`.
  2. **On the paywall's "Restore Purchases" button** (`app/paywall.tsx`'s `handleRestore`): the same two checks, using the root (non-hook) `expo-iap` functions `hasActiveSubscriptions`/`getAvailablePurchases` directly (imported aliased as `...Direct`) rather than the hook's versions, specifically to avoid a stale-closure/double-`initConnection` issue with the hook already mounted on that screen. Shows an `Alert` for restored / not-found / error outcomes.
- **Dev-only reset**: `app/categories.tsx` renders a `__DEV__`-only button that calls `clearPurchase()` for testing.
- **Product IDs are placeholders for store configuration** — `football_imposter_weekly` / `football_imposter_lifetime` must be created in App Store Connect / Google Play Console with matching identifiers before real purchases can succeed; the native `ios/` project also contains `Pro Unlock Test.storekit`, a StoreKit test config, but it is scoped to the *legacy* product id (`com.mzahariev.footballimposter.pro`), not these two.

### 8.2 Legacy/orphaned system: one-time "Pro" unlock
- **Product**: `store/billing.ts` — `IAP_PRODUCT_PRO = "com.mzahariev.footballimposter.pro"` (non-consumable).
- **Purchase state**: `store/proStore.ts`'s `useProStore` (`isPro`), hydrated on launch by `_layout.tsx` but never read by any live screen.
- **Purchase flow**: `store/useBilling.ts`'s `useBilling()` hook (purchase/restore via `expo-iap`), and `components/ui/ProInfoModal.tsx` (the intended UI for it) — **neither is imported by any screen**, so this entire path is unreachable from the running app today. `components/logic/gating.ts`'s `getFreeCount`/`getPlayableItems`/`getAccessLabel` (a 20%-free-items model, distinct from the per-item `free` flags in `data/categories/`) are also only consumed by `ProInfoModal.tsx`.

## 9. The i18n System

### How it works
`app/_layout.tsx` defines the entire i18n layer (no external i18n library is used):
- Twelve dictionaries are `require()`'d directly (not `import`ed) "to avoid Metro/Hermes parsing edge-cases with non-ASCII chars": `components/i18n/{en,es,fr,de,it,pt,nl,pl,tr,ar,sr,sl}.json`.
- `Language` is a union type of the 12 two-letter codes.
- `LanguageProvider` holds `language` state (default `"en"`), loads a previously-saved code from `AsyncStorage` key `"settings.language"` on mount, and validates it against a hardcoded `supported` list before applying it.
- `useLanguage()` exposes `{ language, setLanguage }` from context; `setLanguage(l)` updates state and persists it to `AsyncStorage` (fire-and-forget, errors swallowed).
- `useI18n()` (the hook actually used by every screen) wraps `useLanguage()` and returns `{ language, setLanguage, t }`.

### How `t()` resolves keys
`getTranslation(lang, key, vars)`:
1. `getByPath(TRANSLATIONS[lang], key)` — walks the dotted key (e.g. `"categories.activePlayers"`) through the selected language's JSON object.
2. If that lookup is `undefined`/`null`, falls back to `getByPath(TRANSLATIONS.en, key)`.
3. If the resolved value is a string, runs it through `interpolate()`, which replaces `{{varName}}` placeholders using the `vars` object (missing vars become empty string).
4. If the resolved value is a number or boolean, it's stringified.
5. **If the key is missing from *both* the selected language and English**, `t()` returns the **raw key string itself** (e.g. `"foo.bar"` renders literally) — a deliberate debug aid ("helps spot gaps") rather than a crash or blank string.

### Language switching
`app/settings/language.tsx` renders all 12 languages (with autonyms and flags-free codes) in a card list; tapping one calls `onPick(code)` → `setLanguage(code)` (persists + updates context) → `router.back()`.

### Translation completeness
Verified by diffing every language file's flattened key set against `en.json`:
- `en.json` has **196** leaf keys across 20 top-level sections (`common, languages, home, settings, language, onboarding, onboarding2, onboarding3, setup, players, categories, imposters, game, pass, reveal, voting, results, billing, paywall, dev`).
- All **11 other languages have only 170–172 keys each** — see Known Issues for the exact gap.

## 12. Known Issues, TODOs, and Placeholder Data

No `TODO`/`FIXME`/`HACK`/`XXX` comments exist anywhere in `app/`, `components/`, `store/`, `data/`, `logic/`, `hooks/`, `constants/`, or `theme/` (verified by direct grep). The issues below were found by tracing actual runtime behavior.

1. **`app/index.tsx`'s onboarding-skip check is non-functional.** It reads `AsyncStorage.getItem("onboardingDone")` to decide whether to route to `/home` or `/onboarding`, but **nothing in the entire codebase ever writes that key** (confirmed by grep — `"onboardingDone"` appears exactly once, in this one read). Every cold start of the app will therefore always route to `/onboarding`, even for returning users who have already completed it.

2. **Two disconnected monetization systems coexist.** The legacy one-time "Pro" system (`store/proStore.ts`, `store/billing.ts`, `store/useBilling.ts`, `components/ui/ProInfoModal.tsx`, `components/logic/gating.ts`) is fully implemented but entirely unreachable — no screen renders `ProInfoModal` or calls `useBilling()`. Only `useProStore().hydrate()` runs (in `_layout.tsx`), so the persisted `isPro` value is loaded into memory but never read by any live UI. The active system (`store/purchaseStore.tsx` + `app/paywall.tsx`) is what's actually wired to `app/categories.tsx`.

3. **The per-item `free` flag on premium categories is effectively inert.** `store/gameSettings.tsx`'s `getAllowedWords(data, isPro)` restricts word selection to `free: true` items when `!isPro` — but `isPro` here is `GameSettingsProvider`'s own local `isPro` state, which is initialized `false` and **never set** by anything (`setIsPro` is exposed in the context API but no screen ever calls it). Since every premium category's items are *all* `free: false` (see §7), the "free items" filter always produces an empty list, which the function's own fallback (`free.length ? free : data.words`) turns back into *all* words. In practice this function always returns the complete word list for any category — the real premium gate is entirely at the `app/categories.tsx` UI level (preventing selection of the category at all), not at the word-pool level.

4. **`app/settings/index.tsx` contains unfilled placeholder values**: `const IOS_APP_ID = "YOUR_APP_ID";` (used to build the App Store review-request URL for the "Rate App" button — currently would generate a broken `itms-apps://apps.apple.com/app/idYOUR_APP_ID` link) and `const email = "support@yourdomain.com";` (the "Send feedback" mailto address).

5. **Bundle identifier / IAP product ID mismatch.** `app.json`'s `ios.bundleIdentifier` is `com.anonymous.football-imposter` (Expo's default "anonymous" placeholder prefix — i.e., the app has never been assigned a real bundle ID), while the legacy IAP product id in `store/billing.ts` is `com.mzahariev.footballimposter.pro` — a different reverse-domain prefix. These would need to be reconciled before any real App Store Connect / StoreKit configuration.

6. **The active paywall's product IDs (`football_imposter_weekly`, `football_imposter_lifetime`) are not yet backed by any store configuration** found in this repo — the only StoreKit test config present (`ios/Pro Unlock Test.storekit`) is scoped to the legacy single-product id, not these two.

7. **11 of 12 translation files are missing 24–26 keys present in `en.json`**, most notably the **entire `paywall.*` section** (`heroTitle`, `heroSubtitle`, `weeklyTitle`, `lifetimeTitle`, `restorePurchases`, all error/restore alert copy, etc.) plus `categories.premiumLabel` and one `language.*` pair. Non-English users will see the paywall (and the "Premium" category-lock label) fall back to English text via the `t()` fallback mechanism (§9) rather than their own language.

8. **Dead-but-guarded function references in `app/game.tsx`.** The back-button handler calls `s.resetGame()` and `s.clearSeenPlayers()` behind `typeof s.X === "function"` guards, but neither `resetGame` nor `clearSeenPlayers` is ever defined on `GameSettingsState` — these two calls are permanent, silent no-ops (the equivalent live methods are `resetRound()` and `resetSeenPlayers()`, both of which *are* called alongside them in the same handler).
